# KiCad boards

KiCad 10 projects for TurboACE's boards (requirements.txt), one folder per build, the
same split as release/:

- `standalone/`: the carrier with the keyboard header and its level shifter (drawn)
- `expansion/`: the adapter board, the Tang Nano 20K on a real Jupiter Ace's edge
  connector, with the 3.3 V / 5 V bus buffers (not drawn yet)

Each has a schematic, a PCB with the footprints placed, the board outline and the
design rules set (routed by hand), and the BoM generated from the schematic.

## Generated, then routed by hand

Each board is generated by its `generate.py` from one table of parts, nets and
placement, with `kigen.py` here. It is run with the KiCad AppImage's Python, which
brings KiCad's `pcbnew` module, `kicad-cli` and the libraries:

    APP=toolchain/kicad/kicad-10.0.8-x86_64.AppImage     # ./download_toolchain.sh puts it there
    $APP python3.11 kicad/standalone/generate.py           # make the board, then check it
    $APP python3.11 kicad/standalone/generate.py --check   # check the files as they are

- The schematic is drawn from the table: parts placed (rotated or mirrored where
  that makes the drawing read left to right), wires between the computed pin ends,
  junctions, net labels and power symbols; then saved once by `kicad-cli sch upgrade`,
  so the file is KiCad's own. The netlist check proves every wire lands on its pin.
- The PCB is built from the netlist KiCad exports for that schematic, so net names and
  the symbol-footprint links are KiCad's own.
- The checks: the netlist against the table, ERC, DRC with the schematic-parity check
  (only the unrouted connections may remain), the board geometry that matters, and the
  net classes; then the BoM (`*-bom.csv`) and a schematic PDF.
- `generate.py` refuses to overwrite an existing board: once routed by hand, the files
  are the source. `--force` regenerates an unrouted board, but never one that has any
  tracks, vias or zones, nor while KiCad has the project open (its `~*.lck` files):
  from then on, changes are made in KiCad.

## The project library: `lib/`

KiCad has no Tang Nano 20K, so `lib/make_lib.py` makes TurboACE's own library from
one pin table (Sipeed's v3923 schematic and v3921 drawing):

- `TurboACE:TangNano20K`, symbol and footprint: the module's 40 pins by name (IOnn =
  FPGA pin nn; IO52/IO53 marked as the HDMI DDC lines), pins 1-20 its left header (J6),
  21-40 its right header (J5); the footprint's rows 20.32 mm apart, the module's outline
  on F.Fab and a courtyard over all of it, USB/HDMI marked on the silkscreen.
- `TurboACE:Socket_1x20`: a 1x20 female header for the module, a BoM line only (not on
  the board; the module footprint has the pads).
- `TurboACE:LevelShifter_BSS138_4ch`, symbol and footprint: the Adafruit 4-channel
  BSS138 level shifter (product 757), from Adafruit's Eagle files (CC BY-SA): low side
  GND A4 A3 A2 A1 LV (pins 1-6), high side GND B4 B3 B2 B1 HV (7-12), rows 10.16 mm
  apart.
- `TurboACE:LevelShifter_BSS138_4ch_Gebildet`, symbol and footprint: the same circuit on
  the Gebildet board (a copy of SparkFun's BOB-12009; used on the standalone board).
  Mounted labelled side up, its rows read LV4 LV3 GND LV LV2 LV1 and HV4 HV3 GND HV HV2
  HV1 (the seller's photo, the mirror of SparkFun's top view); pins 1-6 LV1 LV2 LV GND
  LV3 LV4, 7-12 HV1 HV2 HV GND HV3 HV4; rows 10.16 mm apart, 15.24 × 12.7 mm.
- `TurboACE:MiniDIN6_PS2_Female`, symbol and footprint: the PS/2 keyboard socket, 6-pin
  mini-DIN female, right angle, shielded, at the board edge (Mauser 011-0716, from its
  listing's drawing; pins as the Same Sky MD-60S): 1 DATA, 3 GND, 4 +5V, 5 CLK, three
  shield tabs. Its depth is not given there: taken as 13 mm, to measure.

Each board folder's `sym-lib-table` and `fp-lib-table` point at it. Regenerate it with
`$APP python3.11 kicad/lib/make_lib.py`.

`build/` (reports, netlist) and KiCad's per-user files are not kept in git.
